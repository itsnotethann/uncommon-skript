# uncommon-skript

Skript's platform-independent core, split out so it can run somewhere other than Bukkit.

A fork of [skript-minestom](https://github.com/skript-minestom/skript-minestom), which is itself a
fork of [Skript](https://github.com/SkriptLang/Skript). Upstream's `minestom/` is not built here.

## What's different from upstream

Upstream's `common/` threads `org.bukkit.event.Event` through ~150 files and calls Bukkit directly
for scheduling, addon lifecycle, logging and server state. That is replaced here by a platform SPI:

- `org.skriptlang.skript.lang.event` — `PlatformEvent`, `Cancellable`, `EventPriority`
- `org.skriptlang.skript.platform` — `EventBus`, `EventChannel`, `PlatformScheduler`,
  `AddonHandle`, `AddonRegistry`, `PlatformEnvironment`, `LogSink`

There is no Bukkit in `common`. The `org.bukkit.*` compatibility shim is its own optional module.

Two upstream defects were found along the way, both independent of the SPI. Both are fixed
upstream now:

- event handlers dispatched in reverse priority order, so `MONITOR` ran first and observed state
  before the handlers it exists to observe — skript-minestom#31
- parse warnings logged at `INFO`, making them invisible to anyone filtering at `WARN` —
  skript-minestom#32

## Layout

| Path | Built | |
|---|---|---|
| `spi/` | yes | the platform interfaces. 18 files, no dependency on the rest of Skript |
| `common/` | yes | the platform-free core; a tracking fork of upstream's `common/` |
| `domain/` | yes | fork-owned domain interfaces under `org.skriptlang.skript.domain`; no upstream occupant |
| `bukkit/` | yes | optional Bukkit addon support. Depends on `common`; nothing depends on it |
| `testhost/` | yes | a headless host with no game server that boots the core and runs test scripts. Not published |
| `minestom/` | no | inert. Present only so merges from upstream never hit modify/delete conflicts. Do not edit it here |

`settings.gradle.kts` includes `spi`, `common`, `domain`, `bukkit` and `testhost`, which is what makes `minestom/`
inert. `spi` is transitive through `common`, so consumers get it for free.

## Bukkit addons

Optional, in [`bukkit/`](bukkit/README.md). The core does not depend on it.

The retype is what breaks them. `Expression.getArray` is `getArray(PlatformEvent)` here and
`getArray(org.bukkit.event.Event)` upstream, so a Bukkit-compiled addon's method has a different
erasure and is not an override — it loads, enables, registers its syntax, then throws
`AbstractMethodError` the first time an element is evaluated. `bukkit/` rewrites the addon's
bytecode at load time so its descriptors match, and ships the `org.bukkit.*` shim the addon calls
into.

A host picks it up through `ServiceLoader` as an `AddonRegistry`. Without it on the classpath, jars
in `addons/` are skipped with a warning.

Addon support matches upstream skript-minestom's, checked line by line, and adds a first set of
game types upstream lacks — players, worlds, locations — backed by a platform module. Items,
blocks and inventories are not covered on either. See `bukkit/README.md`.

Measured against every addon in the skript-minestom organisation — SkCheese 1.8, skript-gui 1.3.2,
skript-combat 1.0.0, skript-nbs 1.0.1, skript-bdengine 1.3.0, skNoise 1.0.2 — plus skript-reflect
2.6.3 and oopsk 1.0-beta2. All eight load and their syntax parses, same as upstream. skript-reflect
and oopsk run in CI. The six Minestom addons need a Minestom host, which this repo does not have, so
they run through `tools/addontest/` against a host you build; the probes, pinned jar hashes and pass
rules are all in that directory.

## Using it

```
com.github.itsnotethann.uncommonskript:common:1.0.0-alpha.1
com.github.itsnotethann.uncommonskript:domain:1.0.0-alpha.1
com.github.itsnotethann.uncommonskript:bukkit:1.0.0-alpha.1   # optional, runtime only
```

Or as a composite build, which is how skript-minestom consumes it:

```kotlin
includeBuild("../uncommon-skript")
```

## Fork point

`fork-point` tags 68fb2a85, the last commit shared with skript-minestom before the fork. It never
moves. `upstream-base` is a branch at the last upstream commit merged, and is moved forward on each
merge, so the fork delta is the diff against it:

```
git diff upstream-base main -- common/src/main/java
```

Most of that diff is mechanical retyping of the event type and is regenerated by script rather
than by hand; a much smaller set of files carry real logic changes. The only `org.bukkit` left in
`common/` is a string literal in `classExists`, used for platform detection.
